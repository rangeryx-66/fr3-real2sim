5. 释放并完整停车后，Agent 查看真实载荷、开度、相对运动和 F/T—运动图。新开门状态图中 SAM3 未得到有效把手检测，但把手下方的门板条清晰可见。Agent 从该新 RGB-D 选择推板区域，不把检测失败伪装成新的把手重建。

## 首个物理分歧

`UNLOADED_TO_PANEL_PUSH` 后 **0.10417 s（26 帧）**：

- 实测 TCP 速度逐步上升至 **5.0680 mm/s**；同段位置命令 FK 峰值仅 **0.1910 mm/s**，单步关节位置命令变化最大 **0.0001335 rad**。
- 实测 TCP 对命令 FK 的位置误差约 **0.447→0.385 mm**。没有证据支持“一个大位置跳变”是唯一原因；位置/速度目标与近似隐式执行器响应的交接仍需核查。
- 指尖相对新观测门板平面的间距约 **40.20–40.32 mm**，无正法向接触记录，实际角度恒定。结论不仅依赖零载荷报告。
- 腕部保护等效载荷峰值约 **0.0674 N**，原力保护状态正常。此次不是门阻力或推板传力失败，**是在接触前终止的执行入口失败**。

静态 IK/碰撞路线通过不等于动态执行通过。本轮保留了该反例，没有修改命令、执行器、力限值或速度保护后再跑。

## 通信与异步辨识修复

新增隔离的传输/packet 适配，复用原控制器：

- 所有 Agent 操作统一使用原子发布、重复键/非有限值/操作字段完整校验、精确序列号和独立 `ACCEPTED`/`COMPLETED` ACK。同序列并发发布不能覆盖已存在命令。
- 坏消息返回 `PROTOCOL_ERROR`、不执行机器人动作，保留场景并广告下一个序列；不吞掉低层安全异常。实际生成 owner 的接线经过测试。
- `RAW_READY` 在原始输入关闭后发布，含文件哈希；被动 worker 等待前序 `MODEL_READY`，不再静默跳过尚未产生的训练前缀。处理失败/无局部数据明确返回，不成为操作失败门槛；加载运动不等待辨识。

**离线验证：**200 条并发命令、8 类坏消息恢复、8 个同序列生产者仅 1 个获胜；倒序启动真实历史 F/T 包的 worker 仍按依赖顺序汇总，前序训练数据保留。实际物理 episode 的 **11 条命令均有两个 ACK，11 个载荷哈希全部匹配**，无 JSON 竞争。坏消息故障注入为离线测试，未声称在物理 actor 中故意注入过。

两段 packet 分别为 `READY` 和 `NO_LOCAL_DATA`。后者的 26 帧不足以支持原段内导数处理；数据完整保留，未虚构关闭辨识结果，也没有丢掉第一段。
