# Isolated contact-feedback closure development protocol

References: frozen benchmark `bb3a443` and fixed-TCP 45717 diagnostic `1dc554e`. All original benchmark results, source/configuration and successful plans remain unchanged. The unvalidated unconditional CENTER-decrement module is not used in this experiment.

Before execution, analyze all four archived unilateral failures (45623, 45717, 45671, 45916) and positive control 45638. Reconstruct the original TCP centering commands by exact recorded-input replay; compare them with actual simulated TCP poses, finger frames and native contact points/normals. Recorded-input replay cannot certify a new physical outcome.

One normal closed-start native Isaac **45671 grasp-and-hold** episode is permitted, using its original automatically selected grasp/station. No opening, release, regrasp, manual correction or scene stitching. No selected-plan, scoring, Pink, physical model, gain, effort or safety-limit changes. GPU selection uses available memory; other users' processes remain untouched. Our Isaac actors run sequentially.

The independent `jaw_contact_feedback_closure.py` uses actual finger centers, filtered contact loads and measured TCP feedback only. A unilateral event holds aperture while translating toward the loaded finger, derived from the current left-minus-right closing axis. This retreats the loaded finger and advances the opposite finger at fixed aperture. Over the existing 0.08 s sensor averaging interval, measured translation and load change control when slow closure resumes. Load growth pauses closure again; reaching the original preload pauses progression rather than increasing actuator force. Contact thresholds, slow rate, per-step/speed/displacement bounds and LOW_PRELOAD/FORCE_HOLD equations are retained. No force symmetry or additional convergence requirement is used to declare a grasp.

The isolated runner retains the existing 100 s closure budget, IK/collision checks, temporal overload protection, native finite position actuator, telemetry/video and cooperative export. At closure entry it latches the position-command minus measured-joint equilibrium offset, the same technique already used by frozen opening/local correction. This avoids dropping that offset at measured-pose IK handover; no gains are changed and the reference is not reset to hide slip.

Before launch verify generated source and source/config/plan hashes, rotated/reversed finger-frame direction, incremental bounds, monotonic aperture and exact original bilateral preload/hold behavior. Keep all raw 240 Hz contacts, aperture, drive/mimic joint state, TCP/handle transforms and response decisions private. Publish only code, compact metrics and evidence indexes. Stop after the one trial even if it fails; no tuning or additional physical regression in this round.
