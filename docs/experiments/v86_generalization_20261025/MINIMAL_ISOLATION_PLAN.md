# 最小安全隔离方案（待实施，不能据此启动）

## 核查结论

当前隔离记录不是实例级启动门控。terminal_safety.registry_path只拼接共享actor_lock路径，require_clearance不检查episode或instance，launch在prepare之前和获得共享锁后各检查一次。45936、46427、45746均指向同一个文件并全部被拒绝。

因此，把该文件重命名或移走会改变全局启动判断，**不满足最新授权条件3**。当前准备环境还没有实例UUID、独立运行租约与实例安全记录，**条件4也未完成**。不能用新actor_lock路径、旧版入口、隐藏挂载点或直接entry调用代替上述检查。

本方案不改变ABC、物理owner、F/T补偿/估计数学、规划器、抓取策略或任何硬保护阈值。仅涉及launcher资源归属及终态记录边界；目前未修改运行代码。

## 只补三个边界

1. **固定全局门控与资源仲裁。** 保留现有全局safety_hold位置、内容和拒绝规则；保留共同资源互斥锁。新实例也必须在准备前及持锁后经过该全局检查。实例配置不能改写全局路径。
2. **新增实例身份与局部状态。** 每个新episode产生不可复用UUID和新目录，独立命令/响应、控制进程、模型、USD导入缓存、遥测、实例租约锁与实例安全记录。保存PID及进程启动时间、源码/环境/资产hash、父资源域。仅从声明的静态资源构建新World，禁止加载旧stage快照、控制器状态、历史观测、旧命令或运行缓存；只读机器人几何/权重资源可按hash复用。
3. **新实例的接触前准入。** 复用原监督器和无负载自检：当前关节状态/速度、F/T有效性、无负载、碰撞/关节边界和控制器可信性均通过，才开放交互命令。自检失败保持该实例禁止运动并走原终态流程；未知状态不得写成通过。自检/故障/退出分别记录，不用rc=0或进程消失证明停车。

建议数据布局：固定资源域保留global_hold与共享资源锁；instance_UUID目录内保存INSTANCE.json、instance.lock、instance.safety_hold.json、job/commands/responses、TERMINAL_SAFETY及私有证据。全局与实例故障都必须被检查，不能用实例“新建”覆盖全局拒绝。

## 历史归档的严格边界

- 当前旧全局文件**保持原位、原hash并继续拒绝启动**。
- 可新增只读历史索引，指向现有P0审计与原始证据，继续标记NOT_PASS / HARD_STOP_UNPARKED / 控制器停止完成未确认。新增索引不改变安全有效状态。
- 将来只有明确标为INSTANCE作用域的局部记录，在精确进程身份已终止、共享资源已释放、原始字节完整保留的前提下，才可做实例级归档；旧实例UUID仍永久禁止resume。
- **不得自动把当前LEGACY全局记录重新解释成实例记录或迁移走。** 对其作用域的正式分类/解除须有独立、明确且符合既有全局安全流程的凭据；当前条件授权不包含这一步。

## 离线验收后才能考虑部署

至少覆盖：全局hold阻止任意新UUID；畸形/缺失的强制安全记录拒绝；历史实例UUID禁止复用；局部hold不能被其他UUID覆盖；PID复用和租约占用拒绝；共享锁竞争仅一个owner；新世界不能读取旧状态；接触前自检未完成/失败时交互命令拒绝；硬停止不重试、不清锁存；异常退出缺证据仍禁止自动resume。先用无驱动故障注入验证，再复核冻结owner源码。测试不得建立真实仿真接触。
